# Проверка управления вращающимися лучами через condition

Обучен отдельный **conditional** `PointDenoiser`: `conditioner="embedding"`,
16 классов, hidden 128 × 3, **333 698 параметров**, 20 000 CFM updates.
Время модели — `t * 1000`, где `t=1` соответствует шуму, `t=0` — данным.
Метки передаются при каждом вычислении поля. **CFG выключен**:
`guidance_scale=1`, условие при этом сохраняется. Null-режим обучался через
`condition_dropout=0.1`.

Это отдельная демонстрация conditional-маршрутизации. Она не меняет
unconditional SPEC-серию M0/M1/E0/E1 и не доказывает преимущество какого-либо
distillation loss. Открытые циклы обучения и дистилляции находятся в
[notebook13](../../../notebooks/13_conditional_rays_distillation.ipynb).

## Один шум — разные запрошенные лучи

Зафиксированы **256 начальных векторов**, seed `830001`. Каждый вектор повторён
для всех **16 target labels**: всего 4096 выходов, 32 фактических Euler-шага.
Смена target — единственное изменение между соответствующими запусками.
Null-контроль сгенерирован один раз без condition, затем те же 256 выходов
повторены для всех target labels. Модель и шум не переобучались для оценки.

| Проверка | С condition | Null-контроль |
|---|---:|---:|
| Попадание на запрошенный луч, все точки | **4095/4096 · 99.9756%** | 256/4096 · 6.25% |
| Попадание при `r > 0.25R` | **3903/3903 · 100%** | 239/3824 · 6.25% |
| Доля точек при `r > 0.25R` | **95.29%** | 93.36% |
| Различных конечных лучей на один и тот же шум, среднее | **15.9961 из 16** | 1 |
| Шумовые векторы с правильными выходами для всех 16 targets | **255/256** | 0/256 |

Для 3840 запросов, где target отличался от геометрического proxy исходного
шума, конечный луч изменился в **100%** случаев; запрошенный луч получен в
**3839/3840 · 99.974%** случаев. Следовательно, эта модель реагирует на target,
а не сохраняет один и тот же конечный луч при смене condition.

[GIF маршрутизации](condition_routing.gif) и [статическая схема](condition_routing.png)
показывают один и тот же начальный вектор для targets `0, 4, 8, 12`.
Красный обозначает старт, фиолетовый — финиш; траектории состоят из реальных
узлов solver, без привязки выходов к кривой после генерации.

## Что именно измерено

Для этой среды `R=10/11`, `C=16`. Геометрический proxy номера луча вычисляется
из фазы `atan2(y,x) - π/2 - 1.6π(r/R)²/(0.9C)`. Отдельно считается полная
циклическая ошибка относительно **запрошенного** target; аккуратное попадание
на другой луч не получает нулевую ошибку condition.

Все лучи сходятся в центре: точный `r=0` не имеет определённой принадлежности,
а малые радиусы плохо подходят для такого измерения. Поэтому приведены и
outer accuracy, и coverage. Proxy для исходного Gaussian noise за пределами
`R` продолжает фазовую геометрию и **не является евклидовым расстоянием до
ближайшей конечной кривой**. Из этой оценки не следует, что unconditional-модель
всегда выбирает ближайший к старту луч.

Успешная маршрутизация также не доказывает точное воспроизведение толщины
лучей, радиального распределения или оптимальность траекторий. Здесь проверено
влияние condition на направление генерации у одного фиксированного учителя.
