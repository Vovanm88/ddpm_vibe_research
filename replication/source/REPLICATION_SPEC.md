## 1. Что именно проверяется в дипломе

### 1.1. Авторская конструкция [D]

Диплом использует Flow Matching с соглашением **t=0 — данные, t=1 — шум**:

\[
x_t=(1-t)x_0+t x_1,\qquad x_1\sim\mathcal N(0,I),\qquad
\mathcal L_{FM}=\mathbb E\|v_\theta(x_t,t)-(x_1-x_0)\|^2.
\]

Ученик согласует результат нескольких шагов учителя за меньшее число шагов. К попарному MSE добавляется распределенческий штраф в одном из пространств:

\[
\text{endpoint}:\ y;\qquad
\text{displacement}:\ d=y-a;\qquad
\text{joint}:\ [\sqrt{\gamma}\,a,d].
\]

`a` — общее начальное состояние локального перехода. `endpoint` означает конец этого локального перехода, не обязательно финальное изображение.

Для tube-обучения начальное состояние заменяется на

\[
\tilde a=a+\delta(t,h)\eta,\quad \eta\sim\mathcal N(0,I).
\]

**Учитель пересчитывает переход из возмущённого состояния.** Это не обучение на зашумлённом входе со старым таргетом. В формуле (2.51) ширина связана с длиной интервала в эффективной временной координате. Для распределенческого сравнения автор рекомендует общие `t` и `h` внутри батча.

Опорные места: [D, с. 39–48, формулы (2.20)–(2.51)]; реализация пространств сравнения — [D, с. 57–59, листинги 3.3–3.6].

### 1.2. Что нельзя считать установленным по одному PDF

[D, с. 57] описывает получение состояний `FlowMatchTubeSWDStrategy` интерполяцией данных и шума. Это не то же самое, что состояние на фактическом rollout обученного учителя. Для базовой skip-step стратегии дано другое описание. Нужно проверить, действительно ли источники состояний в опубликованных запусках совпадали.

В [D, с. 72] заявлено сокращение 24 → 16 шагов, а основная таблица 4.2 [с. 73] относится к **24 шагам инференса**. В приложении А.3 есть и результаты на 16 шагах:

## 2. Проверяемые гипотезы и основной контраст

**H1 — добавочный эффект OT.** При одинаковых состояниях, таргетах учителя, архитектуре, инициализации, числе обновлений и инференс-сетке `MSE + Sinkhorn(endpoint)` улучшает качество генерации относительно MSE.

**H2 — отдельный эффект tube.** Обучение вокруг состояний улучшает устойчивость rollout; установить, проявляется ли это уже с одним MSE.

**H3 — зависимость от пространства сравнения.** `endpoint`, `displacement`, `joint` могут давать разные результаты. Не предполагать заранее, что endpoint лучший. Эта гипотеза проверяется только в расширенной матрице.

**H4 — практическая полезность.** Дистиллированный ученик должен сравниваться не только с другим учеником, но и с исходной моделью, просто запущенной на той же короткой сетке.

**Главный заранее выбранный контраст:** `E0 − M0` по MMD² в признаках MNIST-классификатора относительно реального test, на целевой сетке 16 шагов. Меньшее значение лучше. `M1 − M0`, `E1 − M1`, взаимодействие OT×tube и остальные метрики — дополнительные контрасты, а не способы задним числом заменить главную метрику.

Для метрики Q, где меньше — лучше, взаимодействие определяется как:

\[
I=(Q_{E1}-Q_{M1})-(Q_{E0}-Q_{M0}).
\]

Отрицательное I означает более благоприятный эффект OT при наличии tube в рамках этой метрики. Оно не доказывает механизм само по себе.

| ID | Попарный MSE | Распределенческий штраф | Tube, ρ |
|---|---|---|---:|
| M0 | да | нет | 0 |
| M1 | да | нет | 0.10 |
| E0 | да | Sinkhorn endpoint | 0 |
| E1 | да | Sinkhorn endpoint | 0.10 |

Один качественно обученный и замороженный учитель. Три парных seed учеников: `101, 202, 303`. Итого **12 основных обучений ученика**, без учёта учителя, классификатора и диагностического toy-стенда. Каждый seed задаёт одинаковую последовательность данных/времён/шумов для всех четырёх методов; разные методы не должны расходиться по данным из-за дополнительного RNG для SWD или диагностики.

Этот минимум проверяет главный endpoint-вывод и отделяет его от tube, но **не проверяет ранжирование всех методов**.

### 3.2. Расширенная матрица: только отдельным запуском

Декартово произведение:

Это 14 режимов на seed; четыре режима MVP входят в эту матрицу и не запускаются повторно. Exact OT на малых батчах и MMD-training-loss — дополнительные диагностические контроли, не обязательная часть MVP.

Расширения в приоритетном порядке: предписанный стресс-тест 32→8; та же матрица для `teacher_rollout` anchors; контроль 24→16; второй независимо обученный учитель; условная генерация; отдельный AE-модуль. Не включать все расширения автоматически.

По умолчанию: одна доступная GPU, суммарный лимит **6 GPU-часов**, диск **8 GiB** для новых артефактов, не более одного GPU-процесса одновременно. ## 4. Данные и модели [P]

### 4.1. Основной стенд: unconditional MNIST

Используй `torchvision.datasets.MNIST` [R4]. Официальные train/test разделения не смешивать. Из train выделить **55 000 train и 5 000 validation**, детерминированно и стратифицированно по цифрам. Test: **10 000** изображений, закрыт для подбора конфигураций. Сохранить индексы и их хеши.

Модель получает одноканальные изображения 28×28. Нормировка для FM: `x = 2 * pixel - 1`, где исходный pixel находится в [0,1]. Аугментации, случайные сдвиги, бинаризация, текстовое условие, guidance и VAE выключены. Метки нужны оценке, но **не подаются генератору** в основном стенде.

Обратное преобразование для оценщика: `(x + 1) / 2`, затем одинаковый для всех методов clamp в [0,1]. До clamp сохранять долю пикселей вне диапазона и максимальное отклонение. MSE траекторий считать в исходном пространстве FM **без clamp**.

### 4.2. Маленький U-Net

Учитель и ученик имеют одинаковую архитектуру: residual U-Net с разрешениями 28→14→7 и обратным повышением, каналами `[32, 64, 128]`, двумя residual-блоками на уровень, GroupNorm и SiLU. Временной embedding: sinusoidal + MLP, выходная размерность 128. Выход — поле скоростей той же формы, без sigmoid/tanh. Dropout, BatchNorm и attention по умолчанию не использовать. Сохранять фактическую архитектуру, число параметров и FLOP-оценку, если она доступна.

Не добавляй conditioning на длину шага в основной сети: для каждой целевой сетки обучается отдельный ученик, а шаг H используется в формуле внешнего перехода. Новое H-conditioning допустимо только отдельным расширением. Это избегает изменения архитектуры между исходной моделью и основными учениками.

**Ученик инициализируется точной копией зафиксированных весов учителя.** Проверить совпадение state_dict хешем. Все параметры ученика обучаются, teacher frozen/eval. Это проверка сокращения числа шагов, а не сжатия числа параметров. Слово «маленький» относится к обеим моделям относительно Z-Image.

### 4.3. Обучение учителя

Независимо выбрать `x0 ~ train`, `x1 ~ N(0,I)` и `t ~ Uniform(0,1)`. Формировать линейный интерполянт и минимизировать средний по batch и пикселям MSE между `v(x_t,t)` и `x1-x0`. Для учителя t можно выбирать независимо на каждый пример; ограничение общего t потребуется в распределенческой дистилляции.

Стартовые параметры: batch 128, AdamW, lr 2e−4, betas (0.9,0.999), weight decay 1e−4, 30 000 обновлений, warmup 1 000, cosine до 10% исходного lr, grad clip 1.0, EMA 0.999. Вычисления сети — float32 по умолчанию; смешанная точность допускается после теста с записью режима. Seed учителя: 41.

При необходимости увеличить обучение **для общего учителя**, не менять его отдельно под разные методы. На validation сохранять FM-loss и фиксированные генерации. До дистилляции зафиксировать один checkpoint (по заранее определённому правилу; стандартно финальный EMA), его SHA-256 и параметры.

### 4.4. Проверка пригодности учителя

Обязательны генерации учителя с Euler на NFE `[8,16,24,32,64,128]`, одинаковым исходным шумом и без изменения весов. Основной teacher — 32 Euler-шага; 128 шагов — дополнительная численная reference, **не истинные данные**.

Проверить конечность результатов, распознаваемость цифр на фиксированной validation-сетке, покрытие цифр и преимущество по feature-MMD над генератором, возвращающим исходный шум. Убедиться, что при увеличении числа шагов численная траектория стабилизируется; не требовать, чтобы каждая метрика качества была монотонной по NFE.

Если учитель не научился генерировать, сначала устранить это. Плохой учитель не является тестом бесполезности OT. Если исходная модель уже одинаково хороша на 16 и 32 шагах, пометить основной стенд как малочувствительный к ускорению; выполнить заранее предусмотренный 32→8 в отдельной таблице. Не выбирать число шагов после просмотра того, где выигрывает OT.

## 5. Время, NFE и точная цель дистилляции [P]

### 5.1. Сохраняем соглашение диплома

Генерация идёт от t=1 к t=0. Для положительной длины шага H:

\[
\operatorname{Euler}(x,t,H;v)=x-Hv(x,t).
\]

Не использовать плюс H и не менять направление времени без явной замены всех формул. Проверить это отдельным тестом с постоянным полем.

### 5.2. Основной режим 32→16

Сетка учителя: `t_i = 1 - i/32`, i=0…32. Сетка ученика: `τ_j = 1 - j/16`, j=0…16. На одном локальном переходе `H=1/16`, `h=H/2`:

\[
u=a-hv_T(a,t),\qquad
y_T=u-hv_T(u,t-h),\qquad
y_S=a-Hv_S(a,t).
\]

Вычислить `y_T` под `no_grad`; `y_S` должен сохранять градиент. На каждом обновлении выбрать один j равномерно из 0…15 и использовать общие t,H для всех точек транспортного батча.

Это **новый чистый 2:1 протокол [P]**, близкий к локальной математической схеме автора, а не буквальное воспроизведение 24→16. Называй baseline `local_multi_step_mse` или M0. Не заявляй, что реализован весь алгоритм Progressive Distillation из внешней статьи, если фактически реализована только эта локальная MSE-схема.

### 5.3. Дополнительный режим 32→8

Та же frozen teacher-сетка, ученик `H=1/8`. Teacher target — четыре Euler-шага длиной 1/32, student — один шаг. Отдельный ученик из исходной копии учителя; не продолжение checkpoint 16-step. Число teacher evaluations на target равно четырём, а не двум.

### 5.4. Контроль 24→16 без скрытой подмены NFE

Отношение 24/16 не равно 2. Нельзя сделать два вызова учителя на каждый из 16 переходов и назвать это 24-шаговым учителем.

Для дополнительного явно определённого протокола возьми teacher Euler-grid из 24 шагов и сгруппируй их по паттерну:

```text
teacher_steps_per_student_step = [2, 1, 2, 1, 2, 1, 2, 1,
                                 2, 1, 2, 1, 2, 1, 2, 1]
```

Получатся 16 student-переходов, покрывающих ровно 24 teacher-шага. `H_j=m_j/24`, начало следующего перехода — конец предыдущего. Это неравномерная student-сетка. Сравни с исходной моделью на **той же сетке** и дополнительно с исходной моделью на равномерной 16-шаговой сетке.

Это предложенный способ однозначно задать эксперимент, **не восстановленная из PDF авторская сетка**. Если аудит найдёт другую авторскую сетку, сохраняй оба протокола раздельно. Число шагов решателя и число вызовов сети NFE логировать отдельно; здесь для Euler они совпадают. Для Heun/RK4 это уже не так.

## 6. Состояния и tube [P, с опорой на D]

Основной источник anchors — `interpolant`, как описано для расширенной 2D-стратегии в [D, с. 57]:

\[
a=(1-t)x_0+t x_1.
\]

Все четыре режима используют **одни и те же** `x0, x1, t, H`. В tube-режимах:

\[
\tilde a=a+\rho H\eta,\qquad\eta\sim\mathcal N(0,I).
\]

В базовых режимах `ã=a`. Оба endpoint и оба displacement считаются относительно одного и того же **ã**. Для joint добавлять именно ã, не исходный невозмущённый a. Учитель делает локальные шаги из ã; повторно использовать endpoint из чистого a запрещено.

Формула `δ=ρH` — специализация (2.51) к линейной эффективной координате и полному интервалу длины H. Здесь δ — стандартное отклонение **на координату**; типичный L2-размер возмущения растёт как δ√D. Не нормировать η до единичной длины молча. Возмущение применяется при обучении и специальных robustness-тестах, **не при стандартной генерации**.

`teacher_rollout` — отдельный источник anchors: выбрать шум и получить состояние на соответствующем узле реального rollout замороженного учителя. Повторить всю сравниваемую четвёрку с этим источником, если включено расширение. Не сравнивать MSE на rollout-состояниях с OT на интерполянтах и не приписывать разницу одному лоссу.

**Важно:** линейный интерполянт отдельной пары «данные–шум» в общем случае не является индивидуальной траекторией маргинального FM-поля. Совпадение промежуточных распределений в идеальной модели не делает отдельные пути одинаковыми. Это различие включить в limitations.

## 7. Математический контракт функций потерь

### 7.1. Попарный лосс

Пусть B — число примеров, D — число координат одного состояния, для MNIST D=784. Тогда

\[
L_{pair}=\frac{1}{BD}\sum_i\|y_i^S-y_i^T\|_2^2.
\]

[M] При общем anchor это в точности равно MSE смещений. Не считать `endpoint MSE + displacement MSE` двумя независимыми видами надзора. В основном протоколе не делить loss дополнительно на H²: для неравномерной сетки это изменило бы вес интервалов. Альтернативную velocity-нормировку можно исследовать отдельно.

### 7.2. Объект распределения

Одна точка распределения — **одно полное изображение/состояние**, развёрнутое в вектор. На вход OT поступают тензоры `[B,P]`; это не `[B*H*W,C]` и не облако пикселей одной картинки. Последний вариант был бы другой постановкой.

Зададим нормированные признаки:

\[
\phi_e(y)=\operatorname{vec}(y)/\sqrt D,\qquad
\phi_d(d)=\operatorname{vec}(d)/\sqrt D,
\]

\[
\phi_j(a,d)=[\sqrt\gamma\operatorname{vec}(a),\operatorname{vec}(d)]/\sqrt D.
\]

У joint P=2D, но знаменатель остаётся √D. Стоимость:

\[
C_{ij}=\|\phi_i^S-\phi_j^T\|^2.
\]

Для joint получаем `(γ||a_i-a_j||² + ||d_i^S-d_j^T||²)/D`. Это явная нормировка [P]; PDF не полностью фиксирует нормировки всех 2D-реализаций. Сохранить отличие в `deviations.md`, а при буквальном воспроизведении исходного кода выделить отдельный `author_literal` режим.

### 7.3. Каноническая дивергенция Синкхорна

Равные веса `a_i=b_i=1/B`, неотрицательный план π с соответствующими маргиналами:

\[
T_\varepsilon(X,Y)=\min_{\pi\in\Pi(a,b)}
\sum_{ij}\pi_{ij}C_{ij}
+\varepsilon\sum_{ij}\pi_{ij}\log\frac{\pi_{ij}}{a_i b_j}.
\]

\[
S_\varepsilon(X,Y)=T_\varepsilon(X,Y)
-\tfrac12T_\varepsilon(X,X)-\tfrac12T_\varepsilon(Y,Y).
\]

Это не просто `<C,π>` с вычитанием двух таких же стоимостей: нужна согласованная регуляризованная целевая функция или эквивалентная корректная dual-реализация. При определении обычной энтропии `H(π)=−Σπlogπ` соответствующий знак — **минус εH**, а не плюс. Источник определения дивергенции: [R2]. Не выводить из неоднозначного знака в PDF, что авторский код обязательно ошибочен.

Предпочтительный путь: корректная библиотечная реализация, проверенная против небольшой float64 log-domain реализации. В GeomLoss `p=2` означает стоимость `0.5*||x−y||²`, `ε=blur²`, а `debias=True` включает self-terms [R3]. Для указанной здесь стоимости `||φ−ψ||²` можно передавать `sqrt(2)*φ` и `sqrt(2)*ψ`, сохраняя `blur=sqrt(ε)`. Проверить численное совпадение, не полагаться только на имена параметров. Бэкенд для малого батча — `tensorized`.

В референсной реализации контролировать невязку обеих маргиналей и разницу значений/градиентов при увеличении числа итераций. Для unit-тестов float64, для обучения OT минимум float32 независимо от AMP сети. Не маскировать неустойчивость безусловным clamp или произвольным `nan_to_num`.

Градиент должен проходить в student cross-cost и **оба аргумента student self-cost**. Teacher detached. Не отсоединять student-признаки при сборе батча. Оптимизации через envelope theorem допускаются после проверки градиентов эталоном; просто остановить градиент всего OT-loss нельзя.

### 7.4. SWD и согласование масштаба

Выбрать K единичных случайных направлений θ в R^P. Для каждого направления использовать **одни и те же θ** у учителя и ученика; отсортировать проекции вдоль B:

\[
L_{SW}=\frac{P}{KB}\sum_{k=1}^K\sum_{i=1}^B
\left[\operatorname{sort}(\Phi_S\theta_k)_i-
\operatorname{sort}(\Phi_T\theta_k)_i\right]^2.
\]

Фактор P компенсирует масштаб единичной случайной проекции: `E[P(θ·r)²]=||r||²`. Он является **нормировкой нового протокола [P]**, не заявлением, что именно так реализован SWD в дипломе. Без этого фактора на признаках, уже делённых на √D, OT-вклад может оказаться мал только из-за размерности. `author_literal` при необходимости повторяет фактическую исходную нормировку отдельно.

Не брать квадратный корень: здесь оптимизируется масштабированный `SW₂²`. SWD — самостоятельный срезанный критерий, не полное W₂, даже при большом K. На обучении K=128; отдельный RNG и новые направления на каждом шаге. На оценке K=1024 и фиксированный независимый банк направлений.

### 7.5. Общий loss и калибровка

\[
L=L_{pair}+\lambda_W L_{dist}.
\]

MVP: `λW=1`, `γ=1`. Это стартовые значения, не оптимальные значения автора. Для Sinkhorn выставить

\[
\varepsilon_{j,rep}=\alpha\,m_{j,rep},\qquad \alpha=0.05,
\]

где m — медиана off-diagonal teacher-to-teacher cost на **фиксированной train-only калибровочной выборке** при данном интервале j и representation. Использовать 256 чистых anchors на интервал; teacher targets соответствуют конкретной сетке. Калибровать до обучения учеников, отдельно для endpoint/displacement/joint, но **одинаково для tube и no-tube**. Сохранять значения в manifest. Нельзя пересчитывать масштаб по текущим student-признакам, которые модель может сжимать.

Для вырожденного m использовать нижнюю границу 1e−8 с предупреждением. Если вырождение массовое, разобраться в причине до запуска. В default MVP H одинаковое, но endpoint/displacement могут иметь очень разные масштабы; логировать реальные ε, не только α.

Раз в 200 обновлений измерять `||∇Lpair||`, `||∇Ldist||`, их cosine и отношение `||λ∇Ldist||/||∇Lpair||` по параметрам ученика. Это диагностический замер без дополнительных optimizer updates. Постоянно нулевой, отсоединённый или подавляющий всё остальное градиент — повод проверить реализацию и масштаб, не готовое доказательство эффекта метода.

### 7.6. Два полезных математических контроля [M]

Для равновзвешенных наборов и заданной стоимости:

\[
W_2^2(\hat\mu_S,\hat\mu_T)\le
\frac1B\sum_i\|\phi_i^S-\phi_i^T\|^2.
\]

Попарное сопоставление — допустимый транспортный план. Поэтому мотивация не должна утверждать, что MSE вообще не контролирует распределения. Возможный эффект OT связан с другим сопоставлением/градиентом при ненулевой ошибке и с поведением вне обучающих состояний.

При большом γ joint-план может почти совпасть с попарным сопоставлением. Измерять diagonal mass `Σ_i π_ii`, энтропию плана и маргинальные ошибки на диагностическом батче. Если joint вырождается в почти MSE, это содержательный результат. При конечном γ joint не является строгим условным OT.

## 8. Toy-стенд: известное распределение и доступная аналитика [P, M]

Используй смесь трёх двумерных нормальных распределений с равными весами, центрами `(-0.6,0)`, `(0.6,0)`, `(0,0.65)` и стандартным отклонением σ=0.15 на координату. Train/validation/test генерируются независимыми RNG; сохранять параметры и seed. Усложнение с σ=0.25 допустимо отдельной фиксированной конфигурацией, не через выбор понравившейся картинки.

Сеть: MLP, три hidden-слоя ширины 128, SiLU, sinusoidal t-embedding размерности 32, линейный выход 2. Учитель: тот же CFM-loss, 10k обновлений, batch 512. Ученики: копии учителя, четыре MVP-loss, batch 128, 3k обновлений, один seed для диагностического пилота. Для итоговых toy-выводов нужны повторные seed, а не один удачный прогон.

Здесь можно независимо вычислять идеальное маргинальное поле линейного интерполянта. Для компоненты k:

\[
q_t=(1-t)^2\sigma^2+t^2,\qquad
b_t=t-(1-t)\sigma^2,
\]

\[
r_k(x,t)=\operatorname{softmax}_k\left(
\log w_k-\frac{\|x-(1-t)m_k\|^2}{2q_t}\right),
\]

\[
v_*(x,t)=\sum_k r_k(x,t)
\left[-m_k+\frac{b_t}{q_t}(x-(1-t)m_k)\right].
\]

Это следует из условного среднего совместно гауссовских `(x_t, x1−x0)` внутри компоненты. Формула — аналитический контроль нового стенда, **не заявленная формула автора диплома**. Проверить концы времени: `v*(x,0)=−x`, `v*(x,1)=x−Σw_k m_k`.

Использовать v* для проверки learned teacher и численного решателя; не подменять им незаметно teacher targets MNIST. Можно интегрировать аналитическое поле RK4 с проверкой сходимости при удвоении числа шагов; всегда учитывать четыре NFE на RK4-шаг.

Оценка toy: exact empirical W₂² через linear assignment на пяти независимых подвыборках по 512 точек; MMD с фиксированным RBF; occupancy ближайших центров и его отличие от **реальной выборки с той же процедурой назначения**, доля точек дальше 3σ от всех центров; local/rollout MSE; визуализация плотностей и траекторий с одинаковыми осями. Nearest-center occupancy при перекрывающихся гауссианах — не истинная скрытая метка компоненты. Высокую log-likelihood не считать достаточной: генератор, выдающий только центры, теряет внутримодовое разнообразие.

## 9. Оценка MNIST: качество не равно сходству с учителем

### 9.1. Независимый небольшой оценщик

Обучи CNN-классификатор на реальном train, выбирай checkpoint по real validation, затем заморозь. Простая архитектура: Conv32→Conv64 с pooling, FC128 и logits10. Нормировка входа [0,1]; слой признаков — фиксированный FC128 после активации перед logits. Не использовать генерации для обучения оценщика.

Рабочий диагностический порог [P]: accuracy real validation ≥99%. При недостижении сначала проверить оценщик или явно снизить доверие к семантической оценке. Это не гарантирует, что классификатор обнаруживает все артефакты. Сохранить checkpoint hash, preprocessing и архитектуру. Classifier test accuracy измеряется один раз после его фиксации.

### 9.2. Главная метрика

**MMD² в признаках MNIST-CNN относительно реальных изображений**, не Inception FID и не «KID из диплома». Название поля: `mmd2_mnist_features_real`.

Признаки стандартизовать фиксированными train-only средними/std по координатам; std floor 1e−6. Не делать отдельную нормировку по каждому сравниваемому набору. Ядро:

\[
k(f,g)=\tfrac13\sum_{s\in\{0.5,1,2\}}
\exp[-\|f-g\|^2/(2s^2\ell^2)],
\]

где ℓ² — медиана попарных квадратов расстояний на фиксированной train-only подвыборке 2 000 real features. Сохранить ℓ и индексы. Для независимых выборок размеров n,m использовать U-statistic [R5]:

\[
\widehat{MMD^2}=\frac{\sum_{i\ne j}k(f_i,f_j)}{n(n-1)}
+\frac{\sum_{i\ne j}k(g_i,g_j)}{m(m-1)}
-\frac{2\sum_{ij}k(f_i,g_j)}{nm}.
\]

Оценка может быть немного отрицательной: **не обрезать её до нуля**. Kernel sums вычислять блоками с корректным исключением диагоналей. Не загружать весь O(n²) тензор одновременно без необходимости.

Validation: 2 000 генераций, заранее фиксированный шум. Final: 10 000 генераций и все 10 000 test-изображений. Те же 10 000 исходных шумов используются всеми методами и baseline при final evaluation. Finite-sample baseline real-vs-real оценивать на непересекающихся real subsets; явно указывать меньшие размеры, если они не совпадают с основной оценкой.

### 9.3. Дополнительные метрики

Разделить отчёт на три блока.

**Качество относительно данных:** main MMD; частоты предсказанных цифр и TV до частот классификатора на real; confidence/entropy; внутриклассовое разнообразие признаков; nearest-neighbor distance до train для диагностики запоминания; фиксированные grids и доля значений вне диапазона. Высокая confidence не доказывает качество, а правильная частота классов не гарантирует разнообразия почерков. Допустим дополнительный Fréchet-distance на тех же MNIST features, но назвать его `FD_MNIST`, не стандартным Inception FID.

**Точность относительно учителя:** paired endpoint MSE, pixel SSIM с явно указанным data_range, class agreement при общем шуме, MSE в общих промежуточных узлах. Сходство с учителем — fidelity, а не независимая оценка истинного качества.

**Стоимость:** реальный NFE, время генерации на batch=1 и batch=128, median/p95 после прогрева и GPU synchronization, peak allocated/reserved memory; время обучения, отдельное время OT, число teacher calls. Сохранять и стоимость общего учителя/классификатора, и добавочную стоимость каждого ученика.

Не сводить эти блоки в один средний ранг: self-comparison учителя автоматически выигрывает метрики его собственного воспроизведения. Для MSE=0 PSNR равен +∞; не подставлять условные 100 dB как обычное измерение.

Для распределенческого сравнения **с учителем** использовать отдельный независимый банк teacher noise либо явно иной парно-зависимый estimator. Общий шум нужен paired MSE, но стандартная двухвыборочная MMD U-statistic предполагает независимость сравниваемых выборок. Основной MMD-to-real этой проблемы не имеет.

### 9.4. Обязательные baseline-строки

В финальной таблице должны быть: frozen original N32, frozen original N16, M0 N16, M1 N16, E0 N16, E1 N16. Frozen original N128 — дополнительная численная reference. Для каждого расширения аналогично добавить frozen original на **его** student-сетке. Показывать seed и uncertainty для обучаемых методов; не изображать одну frozen baseline как три независимых обучения.

По умолчанию оценивать каждого ученика на той сетке, под которую он обучен. Запуск ученика на другой сетке — отдельный OOD-grid тест, а не способ выбрать лучшие числа из всех NFE.

## 10. Локальная устойчивость и накопление ошибки

На отдельном фиксированном наборе состояний оценивать три режима: anchors-интерполянты; состояния настоящего rollout учителя; состояния самостоятельного rollout ученика. Третий набор зависит от метода — указать это, не выдавать его за общий фиксированный набор.

Local error: MSE между одним student macro-step и teacher multi-step из **одного и того же входного состояния**. Rollout error: MSE между траекториями при общем начальном шуме на совпадающих узлах сетки. Сохранить кривые по t, не только финальное значение.

Robustness sweep: `ρ_eval ∈ {0,0.05,0.10,0.20}` с `δ_eval=ρ_eval H`, одинаковые perturbations для сравниваемых методов. Teacher target каждый раз пересчитывается из возмущённого состояния. Измерить raw local MSE и относительную ошибку по отношению к средней энергии teacher displacement с зафиксированным малым denominator floor.

Дополнительная проверка чувствительности — центральные конечные разности локальной карты F по нескольким фиксированным единичным направлениям r:

\[
J_Fr\approx\frac{F(a+\zeta r)-F(a-\zeta r)}{2\zeta}.
\]

Сравнить teacher/student, проверить устойчивость при ζ и ζ/2. Для MNIST начать с 64 состояний и 4 направлений; полного Якобиана не строить. Единичные r здесь — определение derivative-теста, не замена гауссовского tube-шума.

[M] Разложение по возмущению мотивирует проверку производных, но noisy MSE не равно чистому Jacobian-matching во всех случаях: при ненулевом остатке в разложении присутствуют и члены с кривизной. Не объявлять по одному снижению loss доказанную устойчивость длинного rollout.

## 11. Unit-тесты и условия остановки

До полного обучения должны пройти следующие проверки; сохранить `tests_report.json` с фактическими численными ошибками и dtype, а не только словом passed.

| Тест | Требование |
|---|---|
| Знак времени | Для постоянного v=c переход равен x−Hc |
| Покрытие сетки | t убывает от 1 до 0; сумма H=1; для 24→16 сумма m=24, len(m)=16 |
| Учитель vs копия | Одинаковые веса дают одинаковый одиночный forward; при одном teacher substep local loss копии почти нулевой |
| Endpoint vs displacement | Попарные MSE и gradients совпадают при общем anchor |
| Identity | Sinkhorn divergence и SWD для одинаковых наборов ≈0 |
| Permutation | Перестановка точек не меняет OT/SWD, но может менять paired MSE |
| B=1 | Sinkhorn self-debiased loss равен заданной squared ground cost; SWD сравнить с конечным банком проекций, не требовать точного равенства без усреднения |
| Translation | Для X и X+c exact W₂²=||c||²; Sinkhorn проверить при сходимости; масштаб SWD проверить усреднением направлений |
| Exact OT bound | Для маленького батча assignment cost ≤ paired cost + tolerance |
| Student gradients | Ненулевые конечные gradients в student, отсутствие gradients в teacher |
| Self-term gradient | Finite-difference/gradcheck проверяет student self-cost с обоими student-аргументами |
| Solver convergence | Невязки маргиналей малы, удвоение итераций не меняет существенно loss/gradient |
| Library parity | Float64 reference и library совпадают по одному определению стоимости/ε/весов |
| Tube retargeting | При смене anchor меняется teacher target; ρ=0 сводится к no-tube |
| λW=0 | Распределенческая стратегия совпадает с MSE при одинаковых RNG/данных |
| Common RNG | Включение SWD/логирования не изменяет индексы примеров, t и исходный noise |
| Evaluation noise | Хеши initial noise одинаковы для всех методов и NFE, нет num_steps в seed |
| Resume | Несколько шагов continuous run и save/resume согласуются в установленном deterministic-режиме |
| Oracle toy | Аналитическое поле проходит endpoint-тесты и проверку численной интеграции |
| Evaluator | MMD permutation invariant; biased identity-тест отделён от unbiased U-statistic; input preprocessing идентичен |

Для точных алгебраических float64-тестов начать с atol=1e−8/rtol=1e−6; для приближённых OT-тестов определить допуск по solver convergence, а не повышать его до исчезновения ошибки. Не требовать нулевого **unbiased MMD** на одном наборе, поданном с двух сторон: совпадающие выборки нарушают предпосылку независимости и дают другой finite-sample результат.

Дополнительный adversarial sanity test: переставить endpoint между примерами так, чтобы мультимножество endpoint сохранилось. Endpoint OT должен остаться нулевым, paired MSE — обычно вырасти. Для joint использовать отдельную конструкцию с сохранённым мультимножеством displacement, но перестановкой его привязки к различным anchors; displacement OT не увидит перестановку, joint при γ>0 в общем случае увидит. Не смешивать эти два теста.

При NaN/Inf, неверных маргиналях, отсоединённом gradient, утечке test или сломанном seed-протоколе **остановить соответствующую серию и исправить причину**. Не продолжать ради красивой итоговой таблицы. Если ошибка затронула уже выполненные методы, пометить их результаты недействительными и переиграть одинаковые условия.

## 12. Обучение ученика и воспроизводимость

Стартовый режим: 10 000 optimizer updates, batch/OT support 128, AdamW lr=1e−4, betas (0.9,0.999), weight decay=1e−4, warmup 500, cosine до 10% lr, clipping 1.0, EMA 0.999. Главный checkpoint — **финальный EMA при одинаковом числе updates**, не лучший по test. Best-validation checkpoint можно показать дополнительной таблицей по единому правилу.

Упрощённый алгоритм:

```text
freeze teacher; initialize student = exact copy(teacher)
for update in registered_updates:
    j = choose_shared_interval(interval_rng)
    x0, x1 = sample_train_and_noise(data_rng, noise_rng)
    a = interpolant(x0, x1, t[j])
    eta = gaussian(tube_rng)           # отдельный RNG
    a_used = a + rho * H[j] * eta
    with no_grad:
        yT = teacher_microsteps(a_used, t[j], H[j], m[j])
    yS = a_used - H[j] * student(a_used, t[j])
    pair = mean_square(yS - yT)
    phiS, phiT = features(a_used, yS, stopgrad(yT))
    dist = selected_loss(phiS, phiT, fixed_calibration[j])
    loss = pair + lambda_w * dist
    backward; clip; optimizer_step; update_student_ema
    log_scalars_and_save_by_fixed_schedule()
```

У M0/M1 можно не вычислять dist, но переключение этого кода не должно менять RNG остальных операций. Teacher inputs и outputs отсоединены от графа. Для real teacher-rollout anchors стоимость получения a учитывается отдельно.

Создать независимые RNG-потоки для split, teacher-init, student/data-order, t, x1, tube, SWD, previews, final samples и bootstrap. Seed получать через стабильный hash либо фиксированный SeedSequence, не встроенный рандомизированный `hash()`. Промежуточная evaluation не должна менять тренировочный RNG.

Начать с одной GPU. Gradient accumulation **не увеличивает автоматически число точек в одной OT-задаче**. Писать отдельно `micro_batch`, `optimizer_effective_batch` и `ot_support_size`. При OOM уменьшать общий OT support и batch у всей сравниваемой группы до запуска. Не давать Sinkhorn меньший batch, а MSE больший без отдельного анализа.

При дальнейшем DDP проверять differentiable all-gather student-признаков, общие t,H между rank и масштаб gradients относительно single-GPU эталона. Просто склеить detached признаки недостаточно. Распределённое обучение не требуется для MVP.

Зафиксировать Python/PyTorch/CUDA/driver/library версии и lockfile. Не переустанавливать рабочий CUDA-стек без причины. PyTorch не гарантирует побитовую воспроизводимость между всеми платформами и версиями; записать deterministic flags и известные исключения [R6].

## 13. Статистика, подбор и защита от выбора победителя задним числом

В MVP подбор гиперпараметров выключен: сравнивается **заранее заданная конфигурация**, а не оптимальные варианты каждой семьи. Отсутствие преимущества в таком тесте не означает, что у метода нет удачных гиперпараметров вообще.

Для каждого из трёх seed сохранить отдельные значения и парную разность главного контраста. Показать mean и sample std по обучениям, число независимых teacher и student seed. При одном teacher вывод условен относительно этого teacher. Три seed — пилотная оценка устойчивости, не основание для уверенного универсального ранжирования.

Допустим приближённый paired t-интервал для среднего различия с явным указанием малой выборки и предпосылок. Bootstrap по картинкам характеризует только sampling uncertainty фиксированных весов, **не заменяет переобучение моделей**. Не изображать 10k генераций как 10k независимых обучений. Учитывать, что все методы используют общие real reference и noise.

Для сильного подтверждения повторить выбранные заранее контрасты на пяти student seed и по возможности втором teacher. Расширенные сравнения пространств и NFE пометить exploratory; при формальных p-values учитывать множественные проверки.

### Подбор как отдельная зарегистрированная серия

Если включён bounded HPO, использовать только validation и отдельный tuning seed. Для Sinkhorn пример бюджета — 9 trials: λW∈{0.1,1,10} × α∈{0.01,0.05,0.20}, при фиксированном ρ и γ. MSE предоставить сопоставимый trial/GPU-time бюджет настройки lr/weight decay. SWD предоставить не меньшую возможность настройки λ и K, если делается вывод о сравнении семейств.

Не менять одновременно loss, anchor-source, EMA, архитектуру и batch в одной «абляции». Для ρ и γ — отдельные чувствительности с явным бюджетом. После выбора конфигураций **переобучить с нуля из исходных teacher-весов** на final seeds. Tuning checkpoints не включать в final среднее.

Не считать относительный процент улучшения от почти нулевой или отрицательной MMD: основная величина — абсолютная парная разность. Фразу «качество сохранено» использовать только при заранее заданном non-inferiority margin; в MVP такой margin не задан. Интервал, содержащий ноль, означает отсутствие убедительного различия, не доказанную эквивалентность.

### Минимальный run manifest

### Требуемые графики

Нужны отдельные графики качества vs NFE, качества vs training wall-time, local/rollout error vs t, robustness vs ρeval; paired seed differences; фиксированные sample grids; для toy — плотности и траектории. Оси, диапазоны и правила отбора примеров одинаковы между методами. Не отбирать удачные изображения вручную. Более красивые примеры могут идти только дополнительной иллюстрацией с пометкой selection.

## 15. Дополнительные модули, выключенные в MVP

### 15.1. Условный MNIST

Unconditional MNIST не проверяет сохранение зависимости от текстового условия. Для такого расширения добавить class conditioning и сравнить transport within-condition с transport по смешанным классам. В первом режиме весь OT-батч может иметь одну цифру; те же условия применять MSE. Обеспечить сопоставимый support size: разбиение B=128 на десять групп не эквивалентно OT по 128 точкам на класс.

Не добавлять class embedding в joint «для исправления метода» без отдельного имени метода: в показанном 2D joint-листинге PDF явно конкатенируются anchor и displacement, не текстовое условие. Смешанный OT может скрывать ошибку условной привязки при хорошем маргинальном распределении; измерять requested-class accuracy и class confusion.

### 15.2. Автокодировщики на MNIST

Это отдельная проверка [D, с. 34–38, 54–56, 70–71, 84–85]. Режимы: AE-MSE, настроенный VAE, WAE-SW₂², WAE-Sinkhorn; при необходимости VAE+OT. Один общий Conv-encoder/decoder, vector latent 16, одинаковые данные, batch и бюджет. Разница дополнительных µ/logvar heads должна быть указана.

Держать reconstruction MSE одинаковым в чистом сравнении регуляризаторов. В авторском WL1AE одновременно меняется и reconstruction на L1 [D, с. 55]; такой вариант воспроизводить отдельно, не смешивая эффект reconstruction и latent penalty. Для VAE явно определить KL reduction (sum по latent dimensions или mean), β и schedule. Не переносить численное β между разными нормировками.

Оценивать reconstruction MSE/SSIM, linear-probe accuracy с обучением probe только на train, ARI/NMI при фиксированном k=10, silhouette, prior-generated samples и active latent units/KL по координатам. Дополнительный подбор k возможен только по train/validation. В приложении диплома k различается между моделями — фиксированный k здесь является явным изменением протокола.

Провал VAE из таблицы автора (LogAcc≈0.101) не считать свойством всех VAE. Проверить loss scaling, KL domination, decoder range и отсутствие утечек. AE-тест не является проверкой FM-tube-механизма. По умолчанию его не запускать.

### 15.3. Что пока не проверяем

Перенос на 3D-геометрию, TripoSG `light/full`, LoRA больших трансформеров, CLIP-семантику, subjective human preference, CelebA и градиентную оптимизацию транспортного плана. Не подменять отсутствующие человеческие оценки ответами самого агента. По этим пунктам verdict — `out_of_scope`, а не «опровергнуто».

## 16. Как должен выглядеть итоговый отчёт

`REPORT.md` должен содержать краткий ответ на H1–H4, фактически выполненный протокол, таблицу исходных/ученических моделей **на одинаковом NFE**, значения каждого seed, отдельные quality/fidelity/cost блоки, абляцию OT×tube, локальную/rollout диагностику, реальные затраты, результаты математических тестов и все отклонения от источника.

Каждое утверждение выводить из конкретных run IDs и файлов, а не из памяти агента. Не вставлять числа из диплома в таблицу новых результатов. Таблицы и графики генерировать из журналов/метрик автоматически; рядом приводить команду пересборки.

Допустимые статусы отдельных гипотез:

| Статус | Значение |
|---|---|
| `supported_on_small_benchmark` | В зарегистрированном контрасте получено устойчивое улучшение на маленьком стенде; область вывода явно ограничена |
| `mixed` | Метрики, seed, состояния или бюджеты показывают разные направления эффекта |
| `no_advantage_in_tested_setting` | В конкретной проверенной конфигурации преимущества не обнаружено; без универсального отрицания |
| `inconclusive` | Мало мощности/seed, слабый учитель, неготовый evaluator, насыщение метрики или недовыполненный бюджет |
| `implementation_issue` | Найдена конкретная ошибка с воспроизводящим тестом; указать, в каком коде и затронула ли результаты |
| `not_tested` / `out_of_scope` | Контраст не запускался либо не входит в упрощённый стенд |

Для уверенного утверждения преимущества требуются не только меньший training loss и не один удачный seed. Главная метрика должна поддерживать вывод, а fidelity/coverage/diversity/cost — раскрывать компромиссы. Улучшение E1 относительно M0 **без** E1 vs M1 не выделяет эффект OT. Улучшение fidelity без улучшения quality не означает улучшение генерации относительно данных.

Минимальная строка `claims_verdict.json`:

```json
{
  "claim_id": "H1",
  "status": "inconclusive",
  "comparison": "E0_minus_M0",
  "metric": "mmd2_mnist_features_real",
  "schedule": "teacher32_student16_euler",
  "teacher_count": 0,
  "student_seed_count": 0,
  "effect_mean": null,
  "run_ids": [],
  "evidence_files": [],
  "scope": "unconditional_pixel_MNIST",
  "limitations": ["Placeholder: no experiment has been executed yet"]
}
```

Это шаблон, не результат. После выполнения заменить все поля фактическими данными; невыполненные измерения оставлять `null`, не нулями.
