маршрутов вокруг стены при одинаковом условии A/B/стена. Код каждого objective,

Первое сравнение завершено: **48 обучений, 168 оценок**, три training seed.

## Какие методы добавлены

| Метод | Что обучаем | Генерация |
|---|---|---|
| `cfm` | Продолжаем обычный conditional Flow Matching на реальных данных | Euler, 1/2/4 вызова |
| `ot_cfm` | Меняем Gaussian–data coupling через точное Hungarian-сопоставление внутри одного условия | Euler, 1/2/4 вызова |
| `endpoint` | Предсказываем конечную точку траектории frozen Teacher32 из её промежуточного состояния | Euler поля, 1/2/4 вызова |
| `progressive` | Последовательно заменяем два шага предыдущего учителя одним | Отдельные стадии 4/2/1 |
| `reflow` | Обучаем прямые noisy→teacher-endpoint мосты по сохранённым парам | Euler, 1/2/4 вызова |
| `consistency` | Учим одну и ту же clean-проекцию в соседних состояниях teacher flow | Denoise + re-noise, 1/2/4 вызова |
| `shortcut` | Совмещаем FM и совпадение одного длинного перехода с двумя короткими | Модель получает длину перехода |
| `meanflow` | Учим среднюю скорость на интервале, используя поправку через JVP | Модель получает длину перехода |

CFM регрессирует скорость линейного моста между реальными данными и Gaussian noise.
В OT-CFM переставляются шумы внутри batch с одним условием: метки разных лучей
или геометрии разных сцен никогда не сопоставляются между собой. Стены не
передают модели ID верхнего/нижнего обхода.
[Flow Matching](https://arxiv.org/abs/2210.02747),
[minibatch OT-CFM](https://arxiv.org/abs/2302.00482).

`endpoint` — простой регрессионный baseline проекта: цель берётся из полного
teacher rollout, а не из соседнего шага. `progressive` переносит идею двукратного
сжатия sampler в Euler/flow-конвенцию: 32→16→8→4→2→1. На каждой стадии заново
создаются student, EMA и optimizer; новый parent — EMA предыдущей стадии.
[Progressive Distillation](https://arxiv.org/abs/2202.00512).

Endpoint обучается предсказывать clean-конец за один вызов. Применение его поля
через Euler с 2/4 вызовами — отдельная off-target проверка, а не обученные
двух-/четырёхшаговые варианты; это отмечено в каждом manifest и итоговой таблице.

Reflow использует те же сохранённые пары начального Gaussian noise и конца
Teacher32, но переучивает поле на прямых интерполяциях между ними. Случайные
точки на новом прямом мосте отличаются от состояний исходной teacher ODE.
[Rectified Flow](https://arxiv.org/abs/2209.03003).

В flow-adaptation consistency distillation используется функция
`f(x,t)=x-t*v(x,t)`: при t=0 она точно равна x. Предсказание student сравнивается
с detached EMA-проекцией после одного малого шага frozen teacher. В качестве
метрики выбран RMS pseudo-Huber с шириной 0.03. Многошаговая генерация чередует
clean-предсказание с новым зашумлением в линейной CFM-конвенции. Это адаптация
consistency-идеи, с явно описанными отличиями от EDM-расписания оригинальной работы.
[Consistency Models](https://arxiv.org/abs/2303.01469),
[Improved Consistency Training](https://arxiv.org/abs/2310.14189).

Shortcut получает `t` и длительность `d`, а не только уровень шума. Три четверти
batch обучаются обычным FM при d=0; оставшаяся четверть — по среднему двух
EMA half-step velocities. Второй вызов действительно использует результат
первого шага. На минимальном half-step 1/32 используется d=0.
[Shortcut Models](https://arxiv.org/abs/2410.12557).

MeanFlow также предсказывает среднюю скорость. Для native-координат `(x,t,d=t-r)`
target имеет вид `v-d*JVP(u; (v,1,1))`: обе временные координаты изменяются при
фиксированном r. Target и адаптивные веса loss отделены от градиента. В основном
рецепте 75% примеров имеют d=0, остальные используют два отсортированных
logit-normal времени. Поправка JVP проверяется отдельно от обучения.
[MeanFlow](https://arxiv.org/abs/2505.13447).

## Правила первого сравнения

В основном эксперименте все восемь вариантов начинают с одного и того же
обученного parent для своей задачи. CFM и OT-CFM здесь означают продолжение
обучения. Shortcut и MeanFlow тоже используют warm start; оригинальные работы
позволяют обучение с нуля. Дополнительная duration-ветка инициализирована так,
чтобы исходное поле совпадало с parent при любом допустимом d.

Зарегистрированы 48 запусков: 8 методов × 2 задачи × seeds 161/262/363.
На каждый выделено 2000 обновлений по 128 примеров. Progressive делит бюджет
на пять стадий по 400 обновлений; стадии для 4/2/1 вызовов имеют соответственно
1200/1600/2000 накопленных обновлений. У всех сохраняется финальная EMA;
лучший checkpoint по итоговой выборке не выбирается.

Сохранённый train-only bank содержит 8192 teacher-траектории на задачу и
используется всеми seeds. Неудачные teacher-маршруты не фильтруются. Разные методы
потребляют разное число teacher-вызовов и выполняют разный объём вычислений:
одинаковое число обновлений не означает одинаковое время обучения. Стоимость
общего parent и создания bank учитывается отдельно.

Старые M0/E0 с 1000 обновлениями выводятся отдельными историческими контролями.
Разницы между ними и новыми моделями не объявляются парным сравнением seeds.

Новые финальные шумы и reference-сцены открываются после фиксации всех 48 запусков
и необходимых progressive-экспортов. Validation и финальная оценка разделены.
Точные рецепты и seeds заданы в
[регистрации](../replication/reports/method_zoo/registration.json).

## Как выбирать по качеству

Для лучей рядом показываются conditional SWD, попадание в запрошенный луч,
coverage вне центра, радиальное и угловое распределения. Стягивание точек в центр
не должно улучшать рейтинг за счёт отсутствия определённого угла.

Для стен основная метрика — допустимость всех сегментов пути. Дополнительно
считаются оба обхода среди успешных путей по всем условиям, баланс мод,
conditional SWD всего внутреннего состояния и длины успешных маршрутов.
Точные A/B восстанавливаются конструкцией, их совпадение не считается выученным
достижением. Уменьшение MSE к parent описывает fidelity, а не качество геометрии.

Таблицы строятся отдельно для каждой задачи и фактического NFE. Pareto-группы
показывают компромиссы метрик без произвольной взвешенной суммы. Неопределённые
или нечисловые значения не могут попасть на первое место. Парные интервалы
считаются по трём training seeds, условно на одном parent; тысячи сгенерированных
точек не заменяют независимые повторы обучения.

## Визуализации

Сравнения используют одинаковый начальный шум. Дополнительные Gaussian draws
consistency sampler также зафиксированы и повторяются для разных conditions.
Его clean-предсказания и повторное зашумление показываются с настоящими временами;
между solver-состояниями не дорисовываются новые состояния.

Денойзинг всего маршрута и движение частицы по готовому пути — разные анимации.
Красный обозначает старт, фиолетовый — финиш. Веса сохраняются отдельными native
Safetensors; notebook не содержит wheel, весов и выполненных outputs.

## Новый эксперимент в Jupyter

[Открыть notebook 15 в Colab](https://colab.research.google.com/github/Vovanm88/ddpm_vibe_research/blob/research/wasserstein-tube-replication/notebooks/15_conditional_method_zoo.ipynb).
Первая ячейка устанавливает пакет из ветки; следующий блок задаёт `CONFIG`.
Для обучения без готового parent-старта измените параметры перед запуском:

```python
CONFIG["initialization"] = "scratch"
CONFIG["methods"] = ["cfm", "ot_cfm", "shortcut", "meanflow"]
CONFIG["output_dir"] = "replication/artifacts/my_scratch_experiment"
```

Для distillation-методов нужен teacher. Основной опубликованный опыт использует
`initialization="parent"`; scratch-режим проверен как возможность API, отдельного
большого сравнения обучения с нуля в эту таблицу не добавлено.
Общий notebook-harness при этом загружает reference-parent и готовит общий bank
для сравнения. У четырёх data-only методов scratch-параметры независимы от него,
а их objectives не используют teacher targets; это не режим без скачивания parent.

Для native MeanFlow/Shortcut на точках один шаг можно записать напрямую:

```python
import torch
from diffusion_lab import IntervalPointDenoiser

model = IntervalPointDenoiser.from_pretrained(
    "replication/demo/method_zoo_v1/rays/seed161/meanflow/ema_model",
    local_files_only=True,
).eval().requires_grad_(False)
noise = torch.randn(128, 2, generator=torch.Generator().manual_seed(42))
target_ray = torch.zeros(128, dtype=torch.long)
with torch.no_grad():
    samples = noise - model(noise, 1.0, conditions=target_ray, step_size=1.0).sample
```

Здесь `t` и `step_size` нормированы в [0,1]. У обычного `PointDenoiser`
существующая embedding-конвенция использует `t*1000`; notebook-sampler учитывает
это различие. Для нескольких вызовов, consistency re-noising и восстановления
A/B используйте видимый `sample_zoo` из notebook.
